# Venulo â€” Project Documentation

## Architecture

**Monorepo** with two directories:
- `client/` â€” React 18 + Vite 5 + TailwindCSS 3.4 + shadcn/ui
- `server/` â€” Express 4 + Prisma ORM + PostgreSQL

**Production deployment:** Single Express server serves both the API (`/api/*`) and the built Vite client (static files from `client/dist/`). Deployed on Railway.

**Database:** PostgreSQL (Railway). Prisma ORM with soft-delete middleware.

**Auth:** JWT in httpOnly cookies with refresh token rotation. CSRF double-submit cookies. Account lockout after 10 failed attempts. Optional TOTP 2FA.

**Key services:** BullMQ job queue (Redis), Stripe subscriptions, Anthropic Claude API (AI insights, optional), nodemailer (SMTP email), PDFKit (report generation).

## Security Rules for AI Coding Assistants

**NEVER:**
- Remove authentication middleware (`authenticate`) from any route
- Remove ownership checks (`verifyLocationOwnership`, `userId` filters)
- Remove rate limiting from any endpoint
- Expose raw database queries or Prisma errors to the client
- Store secrets in client-side code or VITE_ environment variables
- Log passwords, tokens, full API keys, or 2FA secrets
- Use `dangerouslySetInnerHTML` with user-provided content
- Use `$executeRawUnsafe` with user-provided strings in the query template
- Return `passwordHash`, `refreshTokenHash`, `twoFactorSecret`, or `twoFactorBackup` in API responses
- Create new `PrismaClient()` instances â€” always import from `server/lib/prisma.js`

**ALWAYS:**
- Add rate limiting to new endpoints (use `apiLimiter` at minimum)
- Add input validation (express-validator) to routes accepting user input
- Check ownership before returning user-specific data (`where: { userId: req.userId }`)
- Add new environment variables to `server/utils/validateEnv.js`
- Use `select` in Prisma queries to fetch only needed fields
- Use `sanitizeUser()` before returning user objects
- Use the structured pino logger (`server/utils/logger.js`), never `console.log`
- Handle errors with try/catch and return JSON error responses
- Use parameterized queries (`$1`, `$2`) in any raw SQL

## Destructive Operations Against Production

Written after 2026-09-14, when an authorized instruction to "delete every
account except one" silently also destroyed 10 locations, 4 uploads, 4 reports
and 15,576 transactions. The deletion was legitimate. The failure was that the
cascade was never counted or disclosed, so the result looked like an
unexplained wipe and cost hours of incident investigation.

**Before ANY destructive operation on production data:**

1. **Count the dependent rows first and state them.** The schema declares 30
   `onDelete: Cascade` relations. `User` cascades to `Location`, which cascades
   onward to `Upload`, `Report`, `Transaction` and others, and `Upload` and
   `Report` cascade further still. Deleting N users is never "deleting N rows."
2. **Say the full blast radius before running it**, not after. "This removes 9
   users, 9 locations, 4 uploads, 4 reports and 15,576 transactions" â€” then act.
3. **Take a verified backup first** (`node scripts/backup-encrypted.js`) and do
   not prune or delete existing backups as part of the operation.
4. **Report what actually happened**, including dependent rows removed.

**NEVER run against production:**
- `prisma migrate reset` â€” drops and recreates the schema
- `prisma db push --force-reset`
- `prisma db seed` â€” `server/prisma/seed.js` begins by wiping every table
- Any bare `deleteMany` whose cascade you have not counted

`prisma migrate deploy` is the only Prisma command that is safe on production;
it is what the deploy pipeline runs.

**Do not reseed production to make row counts look healthier.** An empty
production database is a fact, not a bug to paper over.

**One named operator at a time.** Two agents working the same repo have already
collided three times: duplicated encrypted-backup implementations, a clobbered
`scripts/backup-crypto.js`, and simultaneous edits to the same incident
document. Before touching shared infrastructure, check whether it already
exists and who owns it.

**Current ownership:** Codex owns backup, encryption and recovery scripts
(`scripts/backup-crypto.js`, `backup-encrypted.js`, `restore-encrypted-backup.js`,
`verify-local-backup.js`, `verify-restore.js`). Do not edit those without
coordinating.

# Venulo Swarm Protocol

The constitution for Campbell's multi-agent build loop. Muse (Soup), Claude Code,
and Codex coordinate through this repo. Humans approve; agents never merge, deploy,
email, or spend.

## Roles

| Agent | Owns |
|---|---|
| `soup` | Writes briefs, reviews results, files follow-ups. Never touches code directly. |
| `claude-code` | Executes code briefs headlessly on the laptop runner. |
| `codex` | Executes code briefs headlessly on the laptop runner. |
| `human` (Campbell) | Approves merges, deploys, emails, spending. Unsticks `needs-human` briefs. |

## Repo layout

```
venulo-swarm/
  PROTOCOL.md          # this file
  SETUP.md             # laptop setup steps
  SOUP-SIDE.md         # what Soup's scheduled job does
  briefs/
    _TEMPLATE.md       # copy this to create a brief
    YYYY-MM-DD-slug.md # one file per task
  status/
    runner.json        # laptop runner heartbeat (updated every poll)
    soup.json          # Soup's reviewer heartbeat
    tokens.jsonl       # per-run token ledger (one JSON object per line)
    dashboard.json     # aggregated snapshot for the JARVIS dashboard (see DATA-CONTRACT.md)
  results/
    <brief-id>/
      RESULT.md        # outcome summary + branch pointer
      agent-output.txt # full agent log
      REVIEW-soup.md   # Soup's review (written by reviewer job)
  scripts/
    runner.sh          # laptop poller â€” the only thing that invokes coding agents
    new-brief.sh       # helper: new-brief.sh <owner> "<title>" [budget]
```

## Brief lifecycle

```
open â†’ claimed â†’ done
  â†“        â†“
  needs-human (stuck, failed twice, or needs a decision)
```

- `open`: ready for pickup.
- `claimed`: runner picked it up. Prevents double-execution.
- `done`: result recorded in `results/<id>/`. Awaiting review/merge by human.
- `needs-human`: agent failed twice, output was confused, or the brief needs a
  decision only Campbell can make. The runner moves on; Soup surfaces it in the digest.

## Hard rules (enforced by the runner, not just by prompting)

1. The runner NEVER merges to `main`, deploys, sends email, or spends money.
   Code lands on branches named `swarm/<brief-id>`. Campbell merges via PR review.
2. Briefs with `needs_approval: true` are never picked up. Campbell flips the flag
   (or the status) when ready.
3. A brief that fails twice goes to `needs-human`. No infinite retry loops, no
   token bonfires.
4. No secrets in this repo. Ever. No API keys, tokens, passwords, customer data.
   The repo is public so Soup can pull it.
5. Briefs stay small and specific. One task, clear acceptance criteria, relevant
   file paths â€” not whole-repo dumps. (This is the prompt-caching strategy:
   small context in, small context out.)

## Cost routing

- `budget: cheap` â†’ Haiku-class models (`claude -p --model haiku`), trivial tasks:
  refactors, docs, test additions, review summaries.
- `budget: standard` â†’ default models, real feature work.
- Free-tier models (GitHub Models, Groq, etc.) are for Soup-side drafts and
  reviews only â€” never for unattended code changes.
- Overnight/heavy work goes through the runner on the laptop, not through
  metered chat.

## Brief ownership

- `owner: claude-code` / `owner: codex` â€” picked up by the laptop runner.
- `owner: soup` â€” picked up by Soup's scheduled reviewer job. Used for research,
  spec-writing, and review briefs. The runner ignores these.

#!/usr/bin/env bash
#
# venulo-swarm runner â€” polls the shared swarm repo for open briefs and
# executes them headlessly with Claude Code and/or Codex.
#
# Runs on YOUR machine (it drives your local agent CLIs).
#
# Things it will NEVER do (enforced by design, not just by prompting):
#   - merge anything into main (work lands on swarm/<brief-id> branches)
#   - deploy anything
#   - send email / spend money
#   - run briefs marked needs_approval: true
#   - retry a failed brief more than MAX_ATTEMPTS times
#
# Telemetry (feeds the JARVIS dashboard):
#   - status/tokens.jsonl   â€” one JSON object per agent run (token usage)
#   - status/dashboard.json â€” regenerated every pass: agents, briefs, tokens,
#                             XP. The dashboard fetches this single file.
#
set -euo pipefail

# ---------------- config (override via env) ----------------
SWARM_REPO="${SWARM_REPO:-$HOME/venulo-swarm}"  # the shared protocol repo
WORK_REPO="${WORK_REPO:-$HOME/venulo}"          # the app repo agents work in
POLL_INTERVAL="${POLL_INTERVAL:-300}"           # seconds between polls; 0 = single pass
ENABLED_AGENTS="${ENABLED_AGENTS:-claude-code,codex}"
CODEX_MODEL="${CODEX_MODEL:-}"                  # e.g. gpt-5-mini; empty = codex default
PYTHON_BIN="${PYTHON_BIN:-}"                  # python3 preferred; python fallback on Windows
MAX_ATTEMPTS=2
XP_PER_BRIEF=100
# ------------------------------------------------------------

log() { echo "[$(date '+%Y-%m-%d %H:%M:%S')] $*"; }
utcnow() { date -u +%Y-%m-%dT%H:%M:%SZ; }

# frontmatter <file> <key> -> value (first match)
frontmatter() {
  awk -v k="$2" '
    /^---$/ { if (++n == 2) exit; next }
    n == 1 && $1 == k":" { sub(/^[^:]+:[ \t]*/, ""); print; exit }
  ' "$1"
}

# brief_body <file> -> markdown below the frontmatter
brief_body() {
  awk 'BEGIN{n=0} /^---$/{n++; next} n>=2' "$1"
}

heartbeat() { # <state> <detail>
  mkdir -p "$SWARM_REPO/status"
  cat > "$SWARM_REPO/status/runner.json" <<EOF
{
  "agent": "runner",
  "ts": "$(utcnow)",
  "state": "$1",
  "detail": "$2"
}
EOF
}

sync_swarm() {
  cd "$SWARM_REPO"
  git pull --rebase --quiet 2>/dev/null || git pull --quiet 2>/dev/null || true
}

push_swarm() { # <commit message>
  cd "$SWARM_REPO"
  git add -A
  if ! git diff --cached --quiet; then
    git commit -q -m "$1" || return 0
    git push -q || log "WARN: push failed; will retry next loop"
  fi
}

claim_brief() { # <brief file>
  local f="$1" attempts
  attempts=$(frontmatter "$f" attempts); attempts=${attempts:-0}
  sed -i 's/^status: open$/status: claimed/' "$f"
  if grep -q '^attempts:' "$f"; then
    sed -i "s/^attempts: .*/attempts: $((attempts + 1))/" "$f"
  else
    sed -i "s/^status: claimed$/status: claimed\nattempts: $((attempts + 1))/" "$f"
  fi
}

set_status() { # <brief file> <status>
  sed -i "s/^status: .*/status: $2/" "$1"
}

# run_agent <owner> <brief id> <brief file> <workdir> <outdir>
# Runs the agent headlessly. For claude-code, captures --output-format json so
# token usage can be recorded. Writes agent-output.txt. Echoes rc on stdout.
run_agent() {
  local owner="$1" brief_id="$2" brief="$3" workdir="$4" outdir="$5"
  local budget prompt rc=0
  budget=$(frontmatter "$brief" budget); budget=${budget:-standard}
  prompt=$(brief_body "$brief")
  (
    cd "$workdir"
    case "$owner" in
      claude-code)
        if [ "$budget" = "cheap" ]; then
          claude -p "$prompt" --model haiku --output-format json > "$outdir/agent-raw.json" 2> "$outdir/agent-stderr.txt" || rc=$?
        else
          claude -p "$prompt" --output-format json > "$outdir/agent-raw.json" 2> "$outdir/agent-stderr.txt" || rc=$?
        fi
        ;;
      codex)
        if [ -n "$CODEX_MODEL" ]; then
          codex exec --model "$CODEX_MODEL" "$prompt" > "$outdir/agent-output.txt" 2> "$outdir/agent-stderr.txt" || rc=$?
        else
          codex exec "$prompt" > "$outdir/agent-output.txt" 2> "$outdir/agent-stderr.txt" || rc=$?
        fi
        ;;
      *) log "unknown owner: $owner"; rc=1 ;;
    esac
    exit $rc
  ) || rc=$?
  echo "$rc"
}

# record_usage <owner> <brief id> <outdir> <rc>
# Parses agent output for token usage, appends to status/tokens.jsonl.
record_usage() {
  local owner="$1" brief_id="$2" outdir="$3" rc="$4"
  "$PYTHON_BIN" - "$owner" "$brief_id" "$outdir" "$rc" "$SWARM_REPO" <<'PYEOF'
import json, os, sys, datetime
owner, brief_id, outdir, rc, swarm = sys.argv[1:6]
entry = {
    "ts": datetime.datetime.now(datetime.timezone.utc).isoformat(),
    "brief": brief_id,
    "owner": owner,
    "exit": int(rc),
    "input_tokens": None,
    "output_tokens": None,
    "model": None,
}
if owner == "claude-code":
    try:
        raw = json.load(open(os.path.join(outdir, "agent-raw.json")))
        text = raw.get("result", "")
        with open(os.path.join(outdir, "agent-output.txt"), "w") as f:
            f.write(text if isinstance(text, str) else json.dumps(text))
        usage = raw.get("usage") or {}
        entry["input_tokens"] = usage.get("input_tokens")
        entry["output_tokens"] = usage.get("output_tokens")
        entry["model"] = raw.get("model")
    except Exception as e:
        entry["parse_error"] = str(e)[:200]
os.makedirs(os.path.join(swarm, "status"), exist_ok=True)
with open(os.path.join(swarm, "status", "tokens.jsonl"), "a") as f:
    f.write(json.dumps(entry) + "\n")
PYEOF
}

# write_dashboard <current_working_id> â€” regenerates status/dashboard.json
write_dashboard() {
  local working_id="${1:-}"
  "$PYTHON_BIN" - "$SWARM_REPO" "$working_id" "$XP_PER_BRIEF" <<'PYEOF'
import json, os, sys, datetime, glob, re
swarm, working_id, xp_per = sys.argv[1], sys.argv[2] or None, int(sys.argv[3])

def fm(path, key):
    in_fm, seen = False, 0
    with open(path) as f:
        for line in f:
            if line.strip() == "---":
                seen += 1
                in_fm = seen == 1
                if seen == 2:
                    break
                continue
            if in_fm and line.startswith(key + ":"):
                return line.split(":", 1)[1].strip().strip('"')
    return ""

briefs = []
for path in sorted(glob.glob(os.path.join(swarm, "briefs", "*.md"))):
    if path.endswith("_TEMPLATE.md"):
        continue
    bid = os.path.basename(path)[:-3]
    briefs.append({
        "id": bid,
        "title": fm(path, "title"),
        "owner": fm(path, "owner"),
        "status": fm(path, "status"),
        "budget": fm(path, "budget") or "standard",
        "priority": fm(path, "priority") or "normal",
    })

today = datetime.datetime.now(datetime.timezone.utc).date().isoformat()
tokens_today = {}
done_total = 0
for b in briefs:
    if b["status"] == "done":
        done_total += 1
tok_path = os.path.join(swarm, "status", "tokens.jsonl")
if os.path.exists(tok_path):
    with open(tok_path) as f:
        for line in f:
            try:
                e = json.loads(line)
            except Exception:
                continue
            if not e.get("ts", "").startswith(today):
                continue
            o = e.get("owner", "unknown")
            t = tokens_today.setdefault(o, {"input": 0, "output": 0, "runs": 0, "unknown": 0})
            t["runs"] += 1
            if isinstance(e.get("input_tokens"), int):
                t["input"] += e["input_tokens"]
                t["output"] += e.get("output_tokens") or 0
            else:
                t["unknown"] += 1

def agent_state(name):
    for b in briefs:
        if b["owner"] == name and b["status"] == "claimed":
            return {"state": "working", "current_brief": b["id"], "current_title": b["title"]}
    if working_id:
        wb = next((b for b in briefs if b["id"] == working_id), None)
        if wb and wb["owner"] == name:
            return {"state": "working", "current_brief": wb["id"], "current_title": wb["title"]}
    return {"state": "standby", "current_brief": None, "current_title": None}

snap = {
    "updated": datetime.datetime.now(datetime.timezone.utc).isoformat(),
    "agents": {
        "runner": {"state": "online"},
        "claude-code": agent_state("claude-code"),
        "codex": agent_state("codex"),
        "soup": {"state": "standby", "note": "reviewer job enriches this"},
    },
    "briefs": briefs,
    "tokens_today": tokens_today,
    "stats": {
        "done_total": done_total,
        "open": sum(1 for b in briefs if b["status"] == "open"),
        "claimed": sum(1 for b in briefs if b["status"] == "claimed"),
        "needs_human": sum(1 for b in briefs if b["status"] == "needs-human"),
        "xp": done_total * xp_per,
    },
}
os.makedirs(os.path.join(swarm, "status"), exist_ok=True)
with open(os.path.join(swarm, "status", "dashboard.json"), "w") as f:
    json.dump(snap, f, indent=2)
PYEOF
}

pass_once() {
  sync_swarm
  heartbeat "polling" "looking for open briefs"
  write_dashboard ""

  for brief in "$SWARM_REPO"/briefs/*.md; do
    [ -e "$brief" ] || continue
    case "$brief" in *_TEMPLATE.md) continue ;; esac

    local status owner approval
    status=$(frontmatter "$brief" status)
    [ "$status" = "open" ] || continue
    owner=$(frontmatter "$brief" owner)
    case ",$ENABLED_AGENTS," in *",$owner,"*) ;; *) continue ;; esac
    approval=$(frontmatter "$brief" needs_approval)
    if [ "$approval" = "true" ]; then
      log "skipping $(basename "$brief"): needs_approval=true"
      continue
    fi

    local id branch outdir
    id=$(basename "$brief" .md)
    branch="swarm/$id"
    outdir="$SWARM_REPO/results/$id"
    log "picked up brief: $id (owner=$owner)"

    claim_brief "$brief"
    push_swarm "runner: claim $id"

    # fresh branch off main in the work repo
    git -C "$WORK_REPO" fetch -q origin 2>/dev/null || true
    if git -C "$WORK_REPO" show-ref --quiet refs/heads/main; then
      git -C "$WORK_REPO" checkout -q -B "$branch" main
    else
      git -C "$WORK_REPO" checkout -q -B "$branch"
    fi

    heartbeat "working" "$id"
    write_dashboard "$id"
    mkdir -p "$outdir"

    rc=$(run_agent "$owner" "$id" "$brief" "$WORK_REPO" "$outdir")
    record_usage "$owner" "$id" "$outdir" "$rc"

    # commit whatever the agent did, push the branch (never main)

      git -C "$WORK_REPO" commit -q -m "swarm($id): agent work" || true
      git -C "$WORK_REPO" push -q -u origin "$branch" || log "WARN: branch push failed"
    fi
    git -C "$WORK_REPO" checkout -q main 2>/dev/null || true

    local attempts
    attempts=$(frontmatter "$brief" attempts); attempts=${attempts:-1}

    if [ "$rc" -eq 0 ]; then
      cat > "$outdir/RESULT.md" <<EOF
# Result: $id
- brief: [$(basename "$brief")](../../briefs/$(basename "$brief"))
- owner: $owner
- branch: \`$branch\`
- finished: $(utcnow)
- exit: 0

## Summary
Agent completed without errors. Full log in agent-output.txt.
Review the branch diff before merging â€” the runner never merges to main.
EOF
      set_status "$brief" "done"
      write_dashboard ""
      push_swarm "runner: done $id"
      log "done: $id"
    elif [ "$attempts" -ge "$MAX_ATTEMPTS" ]; then
      printf '# Result: %s\n\nFailed %s times. Marked needs-human.\nSee agent-output.txt.\n' "$id" "$attempts" > "$outdir/RESULT.md"
      set_status "$brief" "needs-human"
      write_dashboard ""
      push_swarm "runner: $id needs-human after $attempts attempts"
      log "needs-human: $id"
    else
      set_status "$brief" "open" # back to open; retried next loop
      write_dashboard ""
      push_swarm "runner: $id attempt $attempts failed, will retry"
      log "will retry: $id"
    fi
  done

  heartbeat "polling" "idle"
  write_dashboard ""
  push_swarm "runner: heartbeat"
}

+## 3. Headless compatibility verdict
+
+**Claude Code: yes in principle with normal non-bare loading; unverified on the runner host. Codex: skills are expected through supported discovery/native plugin paths, but Claude Markdown agents and hooks do not automatically become equivalent Codex workers. Actual end-to-end loading remains unverified.**
+
+The runner's `run_agent` changes into `WORK_REPO`, then invokes exactly:
+
+| Owner / route | Invocation |
+|---|---|
+| Claude, cheap | `claude -p "<brief body>" --model haiku --output-format json` |
+| Claude, standard | `claude -p "<brief body>" --output-format json` |
+| Codex, CODEX_MODEL empty | `codex exec "<brief body>"` |
+| Codex, CODEX_MODEL set | `codex exec --model "$CODEX_MODEL" "<brief body>"` |
+
+It does not pass explicit plugin directories, agent definitions, skill names, settings sources, Codex profiles, hook-disable flags, or environment isolation. Configuration and environment are inherited. `budget: cheap` is implemented for Claude; Codex uses the same `CODEX_MODEL` switch regardless of brief budget. Installing only inside the **swarm coordination repo** would not establish project-local discovery from the **work repo**.
+
+### Claude paths and flags
+
+[Official headless documentation](https://code.claude.com/docs/en/headless) says ordinary `-p` loads interactive-equivalent context, including local/user skills, commands, agents, plugins, and hooks. `--bare` skips that discovery; the runner does not use it. Do not introduce bare mode casually: its authentication behavior differs.
+
+Relevant locations are `~/.claude/skills`, `~/.claude/agents`, `~/.claude/commands`, project `.claude/` equivalents, settings files and installed plugin caches. `CLAUDE_CONFIG_DIR` and the launching user's home determine which user configuration is seen; ECC also uses its own roots as above. `--plugin-dir`, `--settings`, `--setting-sources`, `--agents`, and `--agent` can make future loading explicit. Skill/custom command invocation can be put in the headless prompt; discovery alone does not guarantee selection. See [CLI reference](https://code.claude.com/docs/en/cli-reference).
+
+A normal plugin install would bring automatic hooks unless explicitly excluded/disabled. Do not equate `--output-format json` with isolation or tool restrictions.
+
+### Codex paths and flags
+
+Local help confirms user config at `$CODEX_HOME/config.toml` (usual home default `~/.codex`), `-c/--config` overrides, `-C/--cd`, `--enable/--disable`, sandbox controls, `--json`, and `--ephemeral`. This CLI's `-p/--profile` layers `$CODEX_HOME/<name>.config.toml`; it also exposes `--ignore-user-config`. None are passed by the current runner.
+
+ECC's project skill surface is `.agents/skills/<name>/SKILL.md`; native plugin metadata points to its shared `skills/`. Our current session also exposes user skills from `~/.agents/skills` and `~/.codex/skills`, but that alone is not proof of the runner subprocess's effective catalog.
+
+The [ECC Codex configuration](https://github.com/affaan-m/ECC/blob/main/.codex/config.toml) supplies three explicit native roles: `explorer`, `reviewer`, `docs_researcher`, through `[agents.<name>]` and `.codex/agents/*.toml`, with `features.multi_agent=true`. Copying the 68 Claude `agents/*.md` files does not register 68 native Codex roles. Project trust, config validity, role file resolution, and enabled features must be checked in the actual CLI.
+
+Do not copy that reference config wholesale: it includes six npx-backed MCP servers, a `terminal-notifier` command, and profile/config fields that need validation against this installed alpha. The native plugin instead references [.mcp.json](https://github.com/affaan-m/ECC/blob/main/.mcp.json), currently launching `npx -y chrome-devtools-mcp@latest`; native plugin installation is therefore not inherently skills-only either.
+
+The native plugin's hook is separately trust-gated. Availability of `--dangerously-bypass-hook-trust` in local help does not authorize using it. Claude env settings such as `CLAUDE_CODE_SUBAGENT_MODEL` do not configure Codex's models.
+
+Official OpenAI skills/config pages were requested but returned authorization/robots errors through the web tool. Consequently, Codex loader details beyond local help are **ECC implementation/documentation evidence and inference**, not a verified current OpenAI-docs claim. See [ECC Codex notes](https://github.com/affaan-m/ECC#codex-app-and-cli); do a version-specific discovery test before rollout.

+## 4. Token story: mechanisms versus the “up to 60%” claim
+
+The [token optimization guide](https://github.com/affaan-m/ECC/blob/main/docs/token-optimization.md) associates approximately 60% **cost** reduction with choosing Sonnet over Opus. It also recommends a 10,000-token thinking cap, Haiku for subagents, smaller active MCP catalogs, fresh contexts between unrelated tasks, and compaction at logical boundaries. These are settings and workflow choices, not an ECC compression algorithm. The guide's model/default/price assumptions must be checked for the exact model versions before use.
+
+Concrete mechanisms:
+
+| Mechanism | Potential saving | Qualification for our swarm |
+|---|---|---|
+| Cheaper model routing | Lower price per token | Does not imply fewer tokens; runner already routes cheap Claude briefs to Haiku |
+| Lower reasoning budget | Fewer reasoning tokens when the cap binds | Lower maximum is not lower actual usage in every task; failures/retries may erase gains; support depends on model |
+| Lazy skill loading and selective rules | Smaller initial context | Metadata still has a cost; loading all 292 workflows expands selection noise |
+| Fewer MCP tool definitions, CLI alternatives | Smaller tool/schema context | Modern lazy tool discovery may reduce this advantage; CLI output can also be large |
+| Compact after phases, reset between briefs | Less repeated context | Summary generation itself costs tokens; our runner already starts a fresh invocation per brief |
+| Scoped retrieval and subagent summaries | Smaller parent context | Child tokens count too; parent-context savings are not aggregate savings |
+| Memory/instinct reuse | Less repeated discovery and corrections | Adds stored context, background analysis, possible stale guidance, and privacy review |
+| Batch deterministic checks | Fewer agent turns and repeated compiler launches | Useful only when not duplicating existing tests; automatic format writes can expand diffs |
+| Token/cost monitoring | Makes waste visible | Monitoring does not itself save tokens; cumulative/estimated counters are not our ledger |
+
+[Strategic compact](https://github.com/affaan-m/ECC/blob/main/skills/strategic-compact/SKILL.md) implements context-size and tool-count suggestions, not automatic guaranteed compression. Its default tool-count threshold is 50 with later reminders; context thresholds scale with window size. References to third-party token optimizers are not measured savings supplied by this installation. [Token-budget-advisor](https://github.com/affaan-m/ECC/blob/main/skills/token-budget-advisor/SKILL.md) estimates response size heuristically and asks about depth; it is not a tokenizer or hard runtime budget.
+
+**Assessment: plausible as a favorable workload-specific cost comparison; unsubstantiated as a general 60% token reduction or a forecast for Venulo.** No reproducible, quality-matched before/after benchmark supporting that general claim was found in the inspected guide/configuration. For example, moving 75% of equally sized work to a model costing one fifth as much yields 60% lower model charges by arithmetic, with **zero token reduction**. That is an illustrative scenario, not a current price claim. Count retries, reviewers, learning and summary subprocesses before accepting savings.
+
+The runner's `status/tokens.jsonl` currently parses only Claude input/output fields. Codex fields stay null; Claude cache-read/cache-write fields and separate ECC subprocesses are not reconciled. ECC's [cost tracker](https://github.com/affaan-m/ECC/blob/main/scripts/hooks/cost-tracker.js) writes cumulative per-session snapshots, with rate-table estimates and optional harness cost. Summing every Stop row double-counts usage. Do not replace measured nulls with estimates or append these rows directly to the swarm ledger.
+
+Future evaluation metric: total measured input, output, reasoning if exposed, cache read/write, and all child/subprocess usage **per accepted brief**, plus attempts, correctness, review defects and wall time. Compare matched brief sets with/without the selected components at the same model first; test model routing separately. Record unknowns explicitly and deduplicate by run/session identity. Only then test the cost hypothesis.

+## 5. Protocol conflicts and required adaptations
+
+| Swarm rule | ECC interaction | Required boundary |
+|---|---|---|
+| open → claimed → done; runner owns claim | /epic-claim uses GitHub issue state, labels, local SQLite and an audit comment | Disable epic/coordination commands; our brief remains authoritative |
+| Branch swarm/<brief-id> | git-workflow offers feature/fix/trunk patterns; orchestration creates worktrees/workers | Keep branch selection exclusively with runner; no ECC orchestrator |
+| Never merge main or deploy | git-workflow explicitly includes merge then deploy; deployment/operator workflows offer broader actions | Exclude merge/release/deploy workflows and credentials; preserve protocol in every selected role |
+| Never email or spend | email-ops, outreach, billing, agent payments, compute/media services and hidden inference are available | Exclude those components and MCPs; summary/observer model calls off |
+| At most two failed attempts | Autonomous loops/councils can continue inside one runner attempt | Disable loops/automatic retry agents; finite task and timeout limits |
+| Token ledger measures actual runs | ECC cumulative costs, background summaries and model-specific agents create other accounting scopes | Single runner ledger writer; aggregate measured child usage; estimates kept separate |
+| Small briefs / fresh context | Automatic previous-session and instinct injection can import unrelated goals | Default memory off; later isolate by brief and treat recall as evidence |
+| Public swarm repo has no secrets/customer data | Observation/command logs and session summaries may contain sensitive content | Keep raw telemetry private, sanitize report artifacts, never auto-export memory to swarm |
+| One operator per shared infrastructure | Parallel ECC agents/formatters can write the same checkout or backup scripts | No automatic delegation; explicit ownership and file scopes |
+| Existing AGENTS.md security requirements | Generic patterns may introduce new Prisma clients, alternate state libraries, broad data access | Project requirements override generic examples; review selected skill bodies and roles |
+| Result means acceptance, not process completion | Pending plan-canvas approvals can stop headless work; runner treats exit 0 as done | Disable interactive plan canvas; require artifact/acceptance verification in future runner checks |
+| Report files are required | doc-file-warning questions creation of extra Markdown | Disable it or later explicitly allow briefs/results paths |
+| Reproducible worker config | Auto-update/configure/sync can alter future runs; unpinned npx launches | Pin and review once, no auto-update or runtime downloads |
+| Headless completion | Detached tmux/cmd dev servers and desktop notifications outlive/interfere with runs | Disable detachment/notification hooks |
+
+Direct conflict evidence: [/epic-claim](https://github.com/affaan-m/ECC/blob/main/commands/epic-claim.md), [git-workflow](https://github.com/affaan-m/ECC/blob/main/skills/git-workflow/SKILL.md), [operator/module catalog](https://github.com/affaan-m/ECC/blob/main/manifests/install-modules.json), and the hook sources above. These are available conventions/capabilities, not a claim that every ECC installation immediately performs them.
+
+**Existing runner gaps exposed by this review:** comments say prohibitions are enforced, but `run_agent` passes the brief body without a universal protocol preamble, tool denylist, time budget, or isolated config. It cannot by itself prevent commands issued by the child. It also marks exit-0 work done without checking acceptance, and retries use `checkout -B ... main`. ECC orchestration or invisible hook writes would compound these gaps. Address them in a separate authorized brief; no runner changes were made here.

+1. **Finish delivery and pin evidence.** Move this report through a permitted operator on the evaluation branch. Reconcile changing catalogs before copying anything.
+2. **Establish worker containment and accounting first.** Preserve the protocol in root and role prompts, enforce allowed output/branch scope, prohibit merge/deploy/email/spend outside prompts, set finite run limits, and capture Codex structured usage plus Claude cache/child usage. Keep runner as sole lifecycle/ledger owner. Test failures, retries and result verification.
+3. **Pilot five selected skill bodies only:** security-review, verification-loop, backend-patterns, frontend-patterns, and api-design. Review their references/scripts before copying. Adapt guidance to CommonJS Express, ESM React, shared Prisma, ownership checks, validation, pino and our test commands. Add tdd-workflow and e2e-testing only for briefs that actually need them.
+4. **Use project-scoped, manually curated discovery paths.** Claude: selected individual directories under WORK_REPO/.claude/skills. Codex: selected compatible directories under WORK_REPO/.agents/skills. Avoid installing both surfaces into a harness if it discovers duplicates. Preserve current AGENTS.md/CLAUDE.md rather than replacing them. No global config copy, full installer, whole-plugin enable, or legacy sync in this pilot.
+5. **Keep all automatic hooks absent initially.** Exclude hooks.json, codex-hooks.json, Cursor/OpenCode adapters, auto-tmux, autoformat/typecheck, notifications, memory capture, learning, cost hooks and summary inference. `ECC_HOOKS_ENABLED=false` is defense in depth for future reviewed payloads, not a substitute for omitting registrations. Do not set hook_profile=off and assume safety: off is a setup choice, not a recognized runtime profile.
+6. **Add at most two explicit review roles after discovery passes.** Candidate Claude roles: code-reviewer and security-reviewer, adapted to report-only/read-only tools and the selected model budget. Codex: one reviewed native reviewer TOML mapping, not all Markdown agents. Spawn only when a brief authorizes delegation; no automatic orchestration or teams. Return findings to the primary worker, never claim another brief.
+7. **Exclude the rest by default.** Especially epic/PR publishing coordination, orch/multi/dev-team/council/loop systems, git merge/deploy guidance, auto-update/configure/hookify, learned-skill promotion/import, billing/email/outreach/social/compute/payment/media services, all MCP startup declarations, and unrelated languages. +8. **Validate on the real headless host with a separately authorized budget.** First use a local inventory/dry-discovery API if the installed CLI exposes one without model execution. Then, only when inference spending is authorized, run a synthetic read-only brief asking for one selected skill's unique marker/path and a bounded review-role result. Capture effective config paths, loaded catalog, child counts, hook/process activity and ledger entries. Fail if any unexpected process/network request/write occurs. The stub test here is not a substitute.
+9. **Run a matched small pilot and keep only measured gains.** Same model and comparable briefs first. Check completion quality, latency, total tokens, unknown usage, repeated tests and diff scope. Store release/config identities with results. Human review decides promotion; no “60%” target should justify lower quality.
+10. **Consider memory last, manually first.** Start with short reviewed handoff files linked to brief ID, branch and source commit. Only if useful, audit a scoped vault runtime. Do not enable observer, automatic LLM summaries, global promotion or raw transcript export until retention/privacy, Windows survival, permissions and complete accounting are proven. No automatic memory becomes policy.
+
+Rollback for a later pilot: remove only the recorded selected files/entries after checking for user edits; restore recorded configuration snapshots if anything was intentionally changed. Do not prune conversations, learned data, or backups. This report itself installs nothing.

+## 3. Headless compatibility verdict
+
+**Claude Code: yes in principle with normal non-bare loading; unverified on the runner host. Codex: skills are expected through supported discovery/native plugin paths, but Claude Markdown agents and hooks do not automatically become equivalent Codex workers. Actual end-to-end loading remains unverified.**
+
+The runner's `run_agent` changes into `WORK_REPO`, then invokes exactly:
+
+| Owner / route | Invocation |
+|---|---|
+| Claude, cheap | `claude -p "<brief body>" --model haiku --output-format json` |
+| Claude, standard | `claude -p "<brief body>" --output-format json` |
+| Codex, CODEX_MODEL empty | `codex exec "<brief body>"` |
+| Codex, CODEX_MODEL set | `codex exec --model "$CODEX_MODEL" "<brief body>"` |
+
+It does not pass explicit plugin directories, agent definitions, skill names, settings sources, Codex profiles, hook-disable flags, or environment isolation. Configuration and environment are inherited. `budget: cheap` is implemented for Claude; Codex uses the same `CODEX_MODEL` switch regardless of brief budget. Installing only inside the **swarm coordination repo** would not establish project-local discovery from the **work repo**.
+
+### Claude paths and flags
+
+[Official headless documentation](https://code.claude.com/docs/en/headless) says ordinary `-p` loads interactive-equivalent context, including local/user skills, commands, agents, plugins, and hooks. `--bare` skips that discovery; the runner does not use it. Do not introduce bare mode casually: its authentication behavior differs.
+
+Relevant locations are `~/.claude/skills`, `~/.claude/agents`, `~/.claude/commands`, project `.claude/` equivalents, settings files and installed plugin caches. `CLAUDE_CONFIG_DIR` and the launching user's home determine which user configuration is seen; ECC also uses its own roots as above. `--plugin-dir`, `--settings`, `--setting-sources`, `--agents`, and `--agent` can make future loading explicit. Skill/custom command invocation can be put in the headless prompt; discovery alone does not guarantee selection. See [CLI reference](https://code.claude.com/docs/en/cli-reference).
+
+A normal plugin install would bring automatic hooks unless explicitly excluded/disabled. Do not equate `--output-format json` with isolation or tool restrictions.
+
+### Codex paths and flags
+
+Local help confirms user config at `$CODEX_HOME/config.toml` (usual home default `~/.codex`), `-c/--config` overrides, `-C/--cd`, `--enable/--disable`, sandbox controls, `--json`, and `--ephemeral`. This CLI's `-p/--profile` layers `$CODEX_HOME/<name>.config.toml`; it also exposes `--ignore-user-config`. None are passed by the current runner.
+
+ECC's project skill surface is `.agents/skills/<name>/SKILL.md`; native plugin metadata points to its shared `skills/`. Our current session also exposes user skills from `~/.agents/skills` and `~/.codex/skills`, but that alone is not proof of the runner subprocess's effective catalog.
+
+The [ECC Codex configuration](https://github.com/affaan-m/ECC/blob/main/.codex/config.toml) supplies three explicit native roles: `explorer`, `reviewer`, `docs_researcher`, through `[agents.<name>]` and `.codex/agents/*.toml`, with `features.multi_agent=true`. Copying the 68 Claude `agents/*.md` files does not register 68 native Codex roles. Project trust, config validity, role file resolution, and enabled features must be checked in the actual CLI.
+
+Do not copy that reference config wholesale: it includes six npx-backed MCP servers, a `terminal-notifier` command, and profile/config fields that need validation against this installed alpha. The native plugin instead references [.mcp.json](https://github.com/affaan-m/ECC/blob/main/.mcp.json), currently launching `npx -y chrome-devtools-mcp@latest`; native plugin installation is therefore not inherently skills-only either.
+
+The native plugin's hook is separately trust-gated. Availability of `--dangerously-bypass-hook-trust` in local help does not authorize using it. Claude env settings such as `CLAUDE_CODE_SUBAGENT_MODEL` do not configure Codex's models.
+
+Official OpenAI skills/config pages were requested but returned authorization/robots errors through the web tool. Consequently, Codex loader details beyond local help are **ECC implementation/documentation evidence and inference**, not a verified current OpenAI-docs claim. See [ECC Codex notes](https://github.com/affaan-m/ECC#codex-app-and-cli); do a version-specific discovery test before rollout.

+## 4. Token story: mechanisms versus the “up to 60%” claim
+
+The [token optimization guide](https://github.com/affaan-m/ECC/blob/main/docs/token-optimization.md) associates approximately 60% **cost** reduction with choosing Sonnet over Opus. It also recommends a 10,000-token thinking cap, Haiku for subagents, smaller active MCP catalogs, fresh contexts between unrelated tasks, and compaction at logical boundaries. These are settings and workflow choices, not an ECC compression algorithm. The guide's model/default/price assumptions must be checked for the exact model versions before use.
+
+Concrete mechanisms:
+
+| Mechanism | Potential saving | Qualification for our swarm |
+|---|---|---|
+| Cheaper model routing | Lower price per token | Does not imply fewer tokens; runner already routes cheap Claude briefs to Haiku |
+| Lower reasoning budget | Fewer reasoning tokens when the cap binds | Lower maximum is not lower actual usage in every task; failures/retries may erase gains; support depends on model |
+| Lazy skill loading and selective rules | Smaller initial context | Metadata still has a cost; loading all 292 workflows expands selection noise |
+| Fewer MCP tool definitions, CLI alternatives | Smaller tool/schema context | Modern lazy tool discovery may reduce this advantage; CLI output can also be large |
+| Compact after phases, reset between briefs | Less repeated context | Summary generation itself costs tokens; our runner already starts a fresh invocation per brief |
+| Scoped retrieval and subagent summaries | Smaller parent context | Child tokens count too; parent-context savings are not aggregate savings |
+| Memory/instinct reuse | Less repeated discovery and corrections | Adds stored context, background analysis, possible stale guidance, and privacy review |
+| Batch deterministic checks | Fewer agent turns and repeated compiler launches | Useful only when not duplicating existing tests; automatic format writes can expand diffs |
+| Token/cost monitoring | Makes waste visible | Monitoring does not itself save tokens; cumulative/estimated counters are not our ledger |
+
+[Strategic compact](https://github.com/affaan-m/ECC/blob/main/skills/strategic-compact/SKILL.md) implements context-size and tool-count suggestions, not automatic guaranteed compression. Its default tool-count threshold is 50 with later reminders; context thresholds scale with window size. References to third-party token optimizers are not measured savings supplied by this installation. [Token-budget-advisor](https://github.com/affaan-m/ECC/blob/main/skills/token-budget-advisor/SKILL.md) estimates response size heuristically and asks about depth; it is not a tokenizer or hard runtime budget.
+
+**Assessment: plausible as a favorable workload-specific cost comparison; unsubstantiated as a general 60% token reduction or a forecast for Venulo.** No reproducible, quality-matched before/after benchmark supporting that general claim was found in the inspected guide/configuration. For example, moving 75% of equally sized work to a model costing one fifth as much yields 60% lower model charges by arithmetic, with **zero token reduction**. That is an illustrative scenario, not a current price claim. Count retries, reviewers, learning and summary subprocesses before accepting savings.
+
+The runner's `status/tokens.jsonl` currently parses only Claude input/output fields. Codex fields stay null; Claude cache-read/cache-write fields and separate ECC subprocesses are not reconciled. ECC's [cost tracker](https://github.com/affaan-m/ECC/blob/main/scripts/hooks/cost-tracker.js) writes cumulative per-session snapshots, with rate-table estimates and optional harness cost. Summing every Stop row double-counts usage. Do not replace measured nulls with estimates or append these rows directly to the swarm ledger.
+
+Future evaluation metric: total measured input, output, reasoning if exposed, cache read/write, and all child/subprocess usage **per accepted brief**, plus attempts, correctness, review defects and wall time. Compare matched brief sets with/without the selected components at the same model first; test model routing separately. Record unknowns explicitly and deduplicate by run/session identity. Only then test the cost hypothesis.

+## 5. Protocol conflicts and required adaptations
+
+| Swarm rule | ECC interaction | Required boundary |
+|---|---|---|
+| open → claimed → done; runner owns claim | /epic-claim uses GitHub issue state, labels, local SQLite and an audit comment | Disable epic/coordination commands; our brief remains authoritative |
+| Branch swarm/<brief-id> | git-workflow offers feature/fix/trunk patterns; orchestration creates worktrees/workers | Keep branch selection exclusively with runner; no ECC orchestrator |
+| Never merge main or deploy | git-workflow explicitly includes merge then deploy; deployment/operator workflows offer broader actions | Exclude merge/release/deploy workflows and credentials; preserve protocol in every selected role |
+| Never email or spend | email-ops, outreach, billing, agent payments, compute/media services and hidden inference are available | Exclude those components and MCPs; summary/observer model calls off |
+| At most two failed attempts | Autonomous loops/councils can continue inside one runner attempt | Disable loops/automatic retry agents; finite task and timeout limits |
+| Token ledger measures actual runs | ECC cumulative costs, background summaries and model-specific agents create other accounting scopes | Single runner ledger writer; aggregate measured child usage; estimates kept separate |
+| Small briefs / fresh context | Automatic previous-session and instinct injection can import unrelated goals | Default memory off; later isolate by brief and treat recall as evidence |
+| Public swarm repo has no secrets/customer data | Observation/command logs and session summaries may contain sensitive content | Keep raw telemetry private, sanitize report artifacts, never auto-export memory to swarm |
+| One operator per shared infrastructure | Parallel ECC agents/formatters can write the same checkout or backup scripts | No automatic delegation; explicit ownership and file scopes |
+| Existing AGENTS.md security requirements | Generic patterns may introduce new Prisma clients, alternate state libraries, broad data access | Project requirements override generic examples; review selected skill bodies and roles |
+| Result means acceptance, not process completion | Pending plan-canvas approvals can stop headless work; runner treats exit 0 as done | Disable interactive plan canvas; require artifact/acceptance verification in future runner checks |
+| Report files are required | doc-file-warning questions creation of extra Markdown | Disable it or later explicitly allow briefs/results paths |
+| Reproducible worker config | Auto-update/configure/sync can alter future runs; unpinned npx launches | Pin and review once, no auto-update or runtime downloads |
+| Headless completion | Detached tmux/cmd dev servers and desktop notifications outlive/interfere with runs | Disable detachment/notification hooks |
+
+Direct conflict evidence: [/epic-claim](https://github.com/affaan-m/ECC/blob/main/commands/epic-claim.md), [git-workflow](https://github.com/affaan-m/ECC/blob/main/skills/git-workflow/SKILL.md), [operator/module catalog](https://github.com/affaan-m/ECC/blob/main/manifests/install-modules.json), and the hook sources above. These are available conventions/capabilities, not a claim that every ECC installation immediately performs them.
+
+**Existing runner gaps exposed by this review:** comments say prohibitions are enforced, but `run_agent` passes the brief body without a universal protocol preamble, tool denylist, time budget, or isolated config. It cannot by itself prevent commands issued by the child. It also marks exit-0 work done without checking acceptance, and retries use `checkout -B ... main`. ECC orchestration or invisible hook writes would compound these gaps. Address them in a separate authorized brief; no runner changes were made here.

+1. **Finish delivery and pin evidence.** Move this report through a permitted operator on the evaluation branch. Keep runner as sole lifecycle/ledger owner. Test failures, retries and result verification.
+3. **Pilot five selected skill bodies only:** security-review, verification-loop, backend-patterns, frontend-patterns, and api-design. Review their references/scripts before copying. Adapt guidance to CommonJS Express, ESM React, shared Prisma, ownership checks, validation, pino and our test commands. Add tdd-workflow and e2e-testing only for briefs that actually need them.
+4. **Use project-scoped, manually curated discovery paths.** Claude: selected individual directories under WORK_REPO/.claude/skills. Codex: selected compatible directories under WORK_REPO/.agents/skills. Avoid installing both surfaces into a harness if it discovers duplicates. Preserve current AGENTS.md/CLAUDE.md rather than replacing them. No global config copy, full installer, whole-plugin enable, or legacy sync in this pilot.
+5. **Keep all automatic hooks absent initially.** Exclude hooks.json, codex-hooks.json, Cursor/OpenCode adapters, auto-tmux, autoformat/typecheck, notifications, memory capture, learning, cost hooks and summary inference. `ECC_HOOKS_ENABLED=false` is defense in depth for future reviewed payloads, not a substitute for omitting registrations. Do not set hook_profile=off and assume safety: off is a setup choice, not a recognized runtime profile.
+6. **Add at most two explicit review roles after discovery passes.** Candidate Claude roles: code-reviewer and security-reviewer, adapted to report-only/read-only tools and the selected model budget. Codex: one reviewed native reviewer TOML mapping, not all Markdown agents. Spawn only when a brief authorizes delegation; no automatic orchestration or teams. Return findings to the primary worker, never claim another brief.
+7. **Exclude the rest by default.** Especially epic/PR publishing coordination, orch/multi/dev-team/council/loop systems, git merge/deploy guidance, auto-update/configure/hookify, learned-skill promotion/import, billing/email/outreach/social/compute/payment/media services, all MCP startup declarations, and unrelated languages. Keep the 12 archived slash shims disabled. Native plugin installation could be reconsidered only with reviewed packaging that omits hook/MCP surfaces.
+8. **Validate on the real headless host with a separately authorized budget.** First use a local inventory/dry-discovery API if the installed CLI exposes one without model execution. Then, only when inference spending is authorized, run a synthetic read-only brief asking for one selected skill's unique marker/path and a bounded review-role result. Capture effective config paths, loaded catalog, child counts, hook/process activity and ledger entries. Fail if any unexpected process/network request/write occurs. The stub test here is not a substitute.
+9. **Run a matched small pilot and keep only measured gains.** Same model and comparable briefs first. Check completion quality, latency, total tokens, unknown usage, repeated tests and diff scope. Store release/config identities with results. Human review decides promotion; no “60%” target should justify lower quality.
+10. **Consider memory last, manually first.** Start with short reviewed handoff files linked to brief ID, branch and source commit. Only if useful, audit a scoped vault runtime. Do not enable observer, automatic LLM summaries, global promotion or raw transcript export until retention/privacy, Windows survival, permissions and complete accounting are proven. No automatic memory becomes policy.
+
+Rollback for a later pilot: remove only the recorded selected files/entries after checking for user edits; restore recorded configuration snapshots if anything was intentionally changed. Do not prune conversations, learned data, or backups. This report itself installs nothing.
