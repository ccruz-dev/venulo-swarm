**Where the code differs from the audit**
- **G5 (calibration):** Only the web page was wrong. The PDF is written once when the report is generated, using the calibration note from that run, and is then served as a stored file. It already had the original note. The web page rebuilt its note from the current venue profile, and even its wording differed from the PDF's. So both could disagree, but only the web side changed over time.
- **G6 (backfill):** Nothing blocks uploading data older than 28 days. The actual limit is a cooldown: after a report succeeds for a location, the next upload there is refused for 28 days. A new customer could upload one month and then couldn't load earlier months for four weeks. So instead of "allow older data," I waive the cooldown during a backfill window.

**Changes**
1. **Calibration snapshot:**
   - Each report now stores the same calibration note the PDF is printed with, plus whether a venue type was set.
   - The web page reads those stored values and no longer looks at the venue profile at all.
   - Reports made before this change have no stored note, so they show none rather than falling back to the current profile. They also lose the "Set venue type" prompt.
